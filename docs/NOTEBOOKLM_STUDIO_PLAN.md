# dsh Notebook Studio：文献报告与演示文稿实施计划

> 更新日期：2026-09-24。独立仓库：`dsh-notebook-studio/`；一个 dsh 会话对应一个隔离的文献项目。以 Host/Web Client 插件为主体，保留检索技能；不引入独立 MCP 服务。

## 统一侧栏入口与宿主主题（v0.5.1，当前方案）

### 设计与实现

- 唯一入口是 dsh 左侧「插件」上方的 **NotebookStudio**。删除会话标签和会话顶部 Studio 按钮；工作台在宿主主区域显示，保留左侧导航，不再以全屏对话框覆盖整个应用。工作台内部的模型设置仍使用可关闭的对话框。
- 通过公开 `sidebar.panellist` 注册入口，顺序 -10（宿主「插件」为 0）；图标使用 `currentColor`，行样式、选中态、折叠提示由 dsh 管理。通过 `main` 注册工作台，以 `session-maybe` 子槽获取当前会话，避免从私有 store 或 DOM 猜测。
- 「返回对话」调用 `layout.selectPanel(null)`，不改变当前会话。无会话时只显示选择／新建指引，不自动创建项目，不发出项目 RPC。更换项目沿用宿主会话导航；各会话的内存草稿互相隔离，离开再进入仍保留，刷新不保证恢复。
- 使用 dsh 实际 `--dsw-*` 主题变量控制背景、文字、按钮、选中态、边框、焦点及状态提示。移除自定义青绿配色和错误的 `bg-l1` 变量；跟随明暗主题与宿主字体，只有 PDF 文档画布保持白色。
- 不变更 Host、数据库、生成与上传约束，不迁移或删除文献和成稿；更新客户端加载依赖与版本至 0.5.1。

### 验收与边界

- 已通过 `npm run check`：39 个 JavaScript + 2 个 Python 测试。新增客户端注册／注销、唯一入口、顺序、会话作用域、无会话指引、返回导航、主题变量回归。
- Playwright/Chrome 隔离壳加载已安装 dsh 的实际 React、导航行组件和主题 CSS：侧栏入口在「插件」之前，旧入口不存在，明暗主题切换后背景和按钮颜色与宿主 token 一致。1440×1000 和 390×844 无横向溢出；无会话不发送 RPC；会话切换隔离、草稿恢复、正文保存／失败重试、PDF 预览、下载检查、设置、检索、上传均通过。HTTP 400 是刻意模拟的下载错误，其余无页面异常。
- 依据本机 dsh 0.1.6-alpha.2；这不是完整宿主部署验收或最新版本兼容声明。未重启或升级 dsh，未发送真实文献到云端。用户自行重启并刷新后加载新客户端。

## 集中式工作台（v0.5.0，入口已由 v0.5.1 替代）

### 设计与入口

- 用户选择「进入 Studio 后集中整理文献、编辑和生成」，因此主形态是全宽工作台而非聊天输入框旁的小面板。会话顶部增加 Studio 按钮，原 Notebook Studio 标签保留。
- 基于 dsh `0.1.6-alpha.2` 的公开槽位：`conversation.session.header.actions` 只提供会话上下文，没有切换标签的方法。顶部入口用插件自有的原生全屏对话框，不模拟 DOM 点击或改宿主核心布局；返回或 Esc 关闭，归还入口焦点。标签内通过公开 `openView` 返回 Chat。
- 左侧是资料库、上传／文件夹、选择和证据检索；中间是正文编辑和 PDF 预览，大纲降为演示文稿可选视图；右侧是创作类型、提示词、输出格式和可选网络参考。两侧可收起，窄屏纵向排列。顶部汇集项目名、进度、生成和导出，API 配置收纳于齿轮设置。

### 实施范围

1. 保留 30 篇、单篇严格小于 30 MB、会话隔离、选篇冻结、引用校验、按内容配图和工作区自动交付等既有约束。上传离开时取消未完成传输，已入库文件不丢；后台生成继续执行。
2. 增加 `getDocument` 读取真实已生成正文，`saveDocument` 接受允许编辑的文字。报告支持标题、摘要、章节正文和表格结论，演示支持逐页标题、论述、结论和备注。客户端不能改写证据 ID、文献集、网络出处或图片来源；保存前检查成稿是否过期。
3. 保存编辑跳过文本模型，沿用原素材计划重新排版，输出到新版本目录而非覆盖旧稿。启用图片服务时仍可能调用生图模型；用户改写结论后需人工核对语义，不能把结构校验称为事实核实。
4. PPT 来源清单 v3 增加完整 `content`；旧版从实际清单的逐页文本还原，不把当前大纲冒充最终成稿。报告使用已存数据库正文。没有引入新的资料库迁移或独立进程。
5. 两入口共享本页内存中的会话草稿，不存 API 密钥；会话切换隔离。未保存正文时禁用导出并提示，刷新前警告；排版失败保留草稿和重试入口。仅已保存正文与生成任务持久化，浏览器内存草稿不承诺跨刷新恢复。

### 验收结果与未覆盖项

- `npm run check`：36 个 JavaScript、2 个 Python 测试通过。新回归核对 DOCX/PPTX/PDF 的编辑正文、来源不可篡改、旧稿不覆盖、过期版本和跨会话拒绝、零额外文本模型调用及旧 PPT 清单读取。
- 现有 Playwright/Chrome 隔离测试壳加载实际 dsh React 与本版客户端，桌面 1440×1000 和窄屏 390×844 通过入口／返回／焦点、折叠、选篇、正文保存／失败重试、共享草稿／会话隔离、设置、大纲、检索、上传限制、PDF 预览及下载错误拦截。页面身份、非空、无异常遮罩、应用控制台、截图及交互检查通过；故意模拟的 HTTP 400 网络日志除外。
- 不重启或升级正在运行的 dsh，不发送真实文献至云端。插件仍软链接本仓库，用户重启后才能加载新版。真实宿主、Safari／PowerPoint、联网和云端内容质量尚待验收；npm `next` 的 `0.1.7-rc.2` 未做兼容验证。

## 下载链路与界面收敛（v0.4.1）

- 实际排查发现服务器存在完整 15 页成稿，浏览器下载的 PPTX/JSON 却是 0 字节。全部 GET 文件路由增加 dsh 必需的 `requestBody: 'buffered'`，支持 HEAD，空文件拒绝导出。客户端下载先校验响应状态和长度；预览先检查 PDF，不再把错误响应保存成空白成稿。
- 界面分成创作台、资料库、成稿和模型设置。文献列表限高滚动，支持全选/清空；任务历史、详细大纲和保存路径默认折叠；每次仅呈现一种创作类型的主操作，成稿统一预览下载。
- 可选生图最长等待改为默认 600 秒并允许 30–1800 秒配置；连接、超时、取消分别反馈。生图失败只影响对应插图，不应损坏 Office/PDF 下载。通用本机测试图成功耗时约 160 秒，不代表已重新生成用户文献插图。
- 验收升级为实际 HTTP 字节检查、浏览器下载成功/空响应/失败状态和分区交互，避免仅测试业务函数与文件 XML 后就认定前后端链路正常。

## 工作区交付、预览与内容配图（v0.4.0）

- **交付位置**：从 dsh 会话 `header.cwd` 获取工作区，自动保存 DOCX/PPTX、PDF 和来源 JSON 到 `notebook-studio/<安全会话目录>/<report或deck-随机后缀>/`。内部数据库与素材缓存仍在 `~/.dsh/studio/v1/`。重复查看复用副本，重新排版创建新目录，不覆盖用户修改；旧成稿可补存。客户端/模型不能指定任意输出路径，目录符号链接拒绝，保存失败保留下载并提示。
- **预览**：报告、演示成稿新增 PDF 内嵌预览和新窗口查看，界面显示工作区路径；预览和下载遵循同一会话权限。PDF 来自同一成稿结构，不声称是 Office 的逐像素转换。
- **引用修复**：结论长度、引用数量与引用合法性分别校验；不再把超过 120 字误报为没引用。模型第二次调用收到具体失败字段、约束及上次 JSON，漏写引用时提供当前有效编号。仍拒绝不存在的证据，不自动补造出处；旧无效成稿缓存会重建。
- **内容配图**：正文生成时同步规划视觉素材。报告每节 0–2 个，演示每页一个主要视觉区域，总数量由内容决定，取消固定一张文献图/生成图/流程图及固定图表页位。原图从本节/页所引 PDF 中结合页码、图注相关性挑选并避免重复；流程图表达步骤/机制，表格表达比较，AI 图仅解释抽象概念。生成图提示词加入相应正文，按张串行、可复用成功素材；生图失败则本节/页流程图补位并显示降级说明。原始图注与正文关联说明分别保存。
- **验收结果**：`npm run check` 通过 32 个 JS + 2 个 Python 测试；覆盖第六页超长和缺引用的反馈修复、无效引用拒绝、4 节 7 项视觉素材的图文顺序和长图注分页、工作区副本与鉴权预览、符号链接拒绝。隔离 UI 测试壳验证桌面及窄屏预览交互，无控制台错误；未替代真实 dsh 部署验收。现有报告只补存而不改内容，使用新视觉计划需要重新生成。

## 输出截断修复（v0.3.1）

- 本机失败任务停在首篇摘要之前，原实现摘要仅给 1,450 个输出 token；大纲、报告和单页成稿也使用偏紧的固定额度。dsh 的 `max-tokens` 是模型输出未完成，不能把部分 JSON 当成有效成稿。
- 结构化 DeepSeek 请求显式关闭推理输出，摘要/主题/单页给 4,096 token，大纲/报告给 12,000；对 dsh 和自定义 Chat Completions 的长度截断最多增加两次输出额度，最高 32,000，仍失败则明确报错。模型 JSON 无效仍执行独立的结构校验重试，不把长度截断当作格式错误；后台任务保留实际失败阶段。
- 仅用合成模型模拟 `max-tokens`、`finish_reason=length` 和持续截断；`npm run check` 通过 **26 个 JavaScript + 2 个 Python** 测试。未用真实文献或真实云端模型重新运行；用户需在合适时重启已有 dsh 后自行尝试。

## 目标与可验证边界

- 用户可以从**会话聊天框**经已安装的 `dsh-paste-input-plus` 上传，或在 **Studio** 中选择多篇 PDF／选择文件夹上传；两个入口使用同一份按 SHA-256 去重的资料库。每项目最多 **30** 篇，每篇大小必须满足 `0 < bytes < 30_000_000`（严格小于十进制 30 MB）；总容量允许 30 篇合法文件。逐篇反馈重复、损坏、扫描件和超额错误。第一版不做 OCR。
- 在 Studio 设置**文本模型**：选择 dsh 注册的 provider/model，或填写 OpenAI 兼容 Chat Completions 的 Base URL、模型名和 API Key。默认沿用 dsh 的 DeepSeek Flash；自定义密钥仅保存在 Host 侧项目私有 SQLite，界面只看到「已配置」，绝不回传密钥、写入素材清单或日志。
- **图像模型可选**：默认关闭；启用时填写 OpenAI 兼容 `/v1/images/generations` 的 Base URL、模型名及可选 API Key，本机 Qwen 可作为预设。关闭时从大纲到 DOCX/PPTX/PDF 均不得调用图片服务，使用真实文献图、可编辑流程图和证据表格。对远程模型上传文献摘录或提示词前，应由用户确认资料许可。
- 在资料库中勾选本次使用的 PDF（默认勾选全部已索引文献），输入写作提示词后分别生成**报告**或**演示文稿**，在界面选择报告 DOCX/PDF、演示 PPTX/PDF 下载格式。中文为默认语言；报告含标题、执行摘要、分节分析、引文、跨文献对照表、图及参考文献，PPT 默认 16:9、15 页，含原生流程图、证据表、图注和备注。生成的事实须能回溯到本次所选文献 ID 与 PDF 页码；AI 示意图须标注来源和非证据性质。
- 用户可**显式勾选联网参考**；仅向已配置的 dsh `ctx.web.search` 发送提示词提炼出的短检索词，不发送 PDF 正文、摘要或逐页摘录。网络结果只作辅助背景，单独记 URL、标题、摘录、检索时间和 `[Wn]` 编号，不充作 `[n] PDF p.x` 论文证据；未勾选则完全不调用搜索。搜索服务不可用或失败时明确报错，不能悄悄产出缺失网络参考的成稿。
- “与 NotebookLM 媲美或更好”是设计目标，不是未经比较就可宣称的结果。质量验收以内容溯源率、图表清晰度、分页/溢出、可编辑性及用户盲评为准。

## 分阶段实施

1. **配置和安全**：加入会话级设置、可用 dsh 文本模型列表和两种调用路径；API Key 仅在本机数据库中保留，设置读取时脱敏；Base URL 只接受 HTTPS 或回环 HTTP，限制请求/响应大小与超时，错误不暴露认证信息。修改模型时不复用其他模型的摘要缓存。
2. **双入口导入**：聊天框保持原协议和目录所有权验证；Studio 以已认证的 `/studio` RPC 按固定小块顺序上传，服务端只写自己创建的临时文件，检查偏移、大小、最终哈希及会话 ID，再走相同的解析与索引流程。dsh 的 `connection.fetch.register` 仅支持 GET/HEAD，不能伪装 POST 文件上传路由。刷新/中断后临时文件可清理；客户端给的路径不能参与磁盘读取。
3. **提示词、选篇和联网证据**：在生成请求中冻结已索引的 PDF ID 集合；仅对选篇逐篇摘要、分批综合，筛选原图及参考文献。用户开启联网时调用 dsh 搜索，过滤不安全/重复 URL，仅保留有出处的短摘录，记录查询和检索时间。大纲/报告的正文论断至少引用一条选篇的逐页 evidence ID，补充联网引用只能用已检索到的 `[Wn]`；失效引用、无证据或模型 JSON 无效时停止。提示词、选篇、联网模式、模型设置及检索结果参与版本/缓存键。
4. **演示文稿成稿而非大纲排版**：先生成 14 页有逻辑顺序的可编辑大纲，再针对每页带入**真实逐页 PDF 摘录**、相关跨篇要点及可选网络摘录，分批生成短标题、核心结论、2–4 条可核实论述、可讲述的详细备注与引用；逐条验证引用确在当前页给出的证据集中。成稿写入 PPTX/PDF 的可见正文、页脚与备注、来源清单，而非把大纲文本直接丢给排版器。允许从提示词一键执行“大纲→详细成稿→排版”，也保留审核、编辑大纲的两段式流程；重试同版可以复用已验证成稿。
5. **报告与视觉交付物**：报告也基于所选 PDF 逐页证据及可选网络摘录组织详实章节；联网引用明确标注在正文和独立的网络参考清单。报告逐节、演示逐页按正文规划原图、流程图、表格或 AI 概念图，不设全篇固定配额或固定插图页位。原图必须来自本节/页所引 PDF；无原图时不伪造，使用原生流程图和文字表格。生图开启后按计划逐张串行生成并复用成功资产，失效则明确降级。PptxGenJS 和 docx 输出可编辑文件，PDF 用同一**成稿**结构单独绘制/排版，不声称逐像素等同 Office。四种文件自动保存到会话工作区，支持鉴权下载和 PDF 预览，并附含章节/页及原始图注的素材来源 JSON 清单。
6. **验证与发布**：用合成无敏感 PDF 与模拟搜索做端到端测试；覆盖选篇隔离、默认离线、明确联网失败、伪造 URL/引用、PPT 成稿不是大纲、格式选择、去重/断点及下载鉴权。解压 DOCX/PPTX 断言实际成稿、引用和备注存在，检查 PDF 页数、中文可提取和有界布局；再人工检查代表性成稿。不要自动向云端发送现有真实文献，亦不停止或重启用户已有 `dsh web` 进程。

## 接口和状态

- 既有 `listSources`、`search`、`generateOutline`、`saveOutline`、`renderDeck`、`retrySource`、`getJob`、`downloadDeck` 保留；已增加 `listModels`、`getSettings`、`saveSettings`、上传 RPC、`generateReport`、`renderReport`、`downloadReport`；本轮增加 `generateDeck` 一键流程及 `sourceIds`、`includeWeb` 请求选项。长任务可轮询，阶段及逐篇错误入 SQLite；失败不能呈现为已完成。
- `~/.dsh/studio/v1/<安全会话目录>/` 存 SQLite、PDF 副本、候选图和内部成稿缓存；数据库文件为私有权限。`workspace_exports` 记录自动保存在会话工作区的交付物路径；保存失败返回明确警告。导出/预览 URL 仅按当前会话和数据库记录中的 ID 寻址，不接受任意文件路径。
- PPT/报告 PDF 从同一结构数据生成，不能宣称是 Office 逐像素转换。若字体不可用，明确报错并提示配置 `STUDIO_CJK_FONT`，不可静默丢失中文。

## 本轮成稿及联网验收（合成资料已完成）

- 未选择文献、选入未完成文献、跨会话伪造 ID 必须拒绝；选篇之外的内容不进入摘要、图片、引用及参考文献。已有大纲只绑定创建它时的选篇和联网结果，重新勾选不暗改旧版。
- 关闭联网时调用计数为零；开启时每次仅搜索提示词关键词且失败可见。联网摘要与 URL 不得标为论文页码，来源清单保留查询时间；不得因搜索结果没有摘要而杜撰信息。
- 用合成证据验证幻灯片正文、结论和讲者备注是成稿阶段新生成的内容，而非简单复制大纲；模型试图引用未传入的 PDF 片段或不存在的网络编号必须报错。报告亦须分别测试 DOCX/PDF 的联网出处与所选文件范围。
- 格式选择在生成前展示，生成后仅一键下载选中的格式，其他格式仍可按需切换；下载继续由后端验证会话归属和文件 ID。
